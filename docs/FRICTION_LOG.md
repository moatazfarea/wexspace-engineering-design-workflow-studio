# Observed friction and fixes

1. **Local HTTP preview**: clicking a guided request initially failed because `crypto.randomUUID` and Web Crypto SHA256 require a secure context on this preview origin. The application now uses `getRandomValues` for operation identifiers and a SHA256 fallback checked against independent Node vectors. HTTPS protection was not disabled. The same UI request then changed the actual room to width 4.5 m and floor 27 m2.
2. **Python SDK version transition**: the existing official MCP 2.3.0 installation uses MCPServer, not the old FastMCP import. Its actual API was inspected and used directly; no unnecessary reinstall was performed.
3. **Expected domain errors**: a rejected room change initially became a generic SDK error. It now returns the SDK ToolError with the actual bounded input/constraint classification. Runtime rejection was tested.
4. **Recovery harness**: the first test confused an intentionally retired test process with a required live process. Seven real HTTP steps had already succeeded. The harness was repaired and resumed against the preserved revision, proving new-process recovery without duplicating the edit. Both receipts are retained.
5. **Current browser surface**: the preview browser does not expose document.modelContext. The interface truthfully reports that limitation. WebMCP invocation is not claimed from source registration; a separate deployed stateless MCP tool surface is provided for actual client verification.
6. **Gated Alexa tools**: the official hackathon FAQ says gated preview SDK/CLI tools are unavailable to participants. The project uses the expressly supported self-hosted MCP and disclosed simulated-experience routes. It does not claim a privileged Alexa account or live Alexa device connection.
